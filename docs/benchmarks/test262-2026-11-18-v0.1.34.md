7,614 files are skipped: Temporal (an ES2026 feature), stage 3 proposals,
proper tail calls (not implemented by Chrome or Firefox either) and the two
`CanBlockIsFalse` tests. The 0.1.11 record executed 45,848 files and passed
45,262 (98.72 %); the multi-agent `Atomics` tests and the
`Intl.NumberFormat-v3` tests now run as well.

Main changes since that record:

- `SharedArrayBuffer` memory is shared between agents (threads) and `Atomics`
  use real atomic operations, blocking `wait`, cross-agent `notify` and
  `waitAsync` timeouts. The runner implements `$262.agent` with threads, so
  the 119 multi-agent tests run: `built-ins/Atomics` passes 387 of 387.
  As in shell hosts, the main agent may block.
- Module graphs are evaluated with the specification's cycle-aware
  algorithm (top-level `await` in cycles).
- Intl (from 51.7 % to 98.6 % of the executed ECMA-402 tests):
  `Intl.DurationFormat`; UTS #35 locale identifiers; specification-level
  `NumberFormat` (including rounding modes, increments and priorities,
  `formatRange`), `PluralRules`, `DateTimeFormat` (time zones, calendars,
  ranges), `Locale`, `ListFormat`, `RelativeTimeFormat`, `DisplayNames`,
  `Segmenter` and `Collator`; locale-sensitive case mapping.
- Smaller fixes: arrow function `toString()`, `Function()` parameter and body
  parsing, class field initialisation order, async generator returns.

Remaining failures outside Intl: three `Date.prototype.toISOString` tests that
depend on the Europe/Madrid offset in the year −271821 (they pass with
`TZ=UTC`), two tests of the legacy `arguments.callee.caller` extension, one
assignment-ordering test for an undeclared global in strict code, one Annex B
test that contradicts SpiderMonkey's staging tests, and 23 SpiderMonkey
staging tests. In Intl, the Chinese and Korean lunisolar calendars are not
implemented (6 tests).
