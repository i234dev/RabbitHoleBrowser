# Bounded GLSL preprocessing

The software shader compiler preprocesses tokens before its existing GLSL ES 100/300
grammar and type checker. A macro can select or construct supported shader code; it
does not add runtime language features, rendering APIs or extension support. This
milestone is not a WebGL conformance or Three.js compatibility claim.

The implementation follows the applicable portions of
[GLSL ES 1.00 sections 3.3/3.4/10.32](https://registry.khronos.org/OpenGL/specs/es/2.0/GLSL_ES_Specification_1.00.pdf),
[GLSL ES 3.00 sections 3.1/3.4/3.5](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf),
and the [WebGL preprocessing rules](https://registry.khronos.org/webgl/specs/latest/1.0/#SUPPORTED_GLSL_CONSTRUCTS).

## Supported operations

- Object-like and function-like macros, empty replacements, `#undef`, matching
  redefinitions and argument-count checking. Replacement operates on whole tokens,
  prescans arguments that are actually substituted, and rescans replacements.
  Per-token hide sets suppress recursive macro reapplication. Macro calls can span
  ordinary source lines; directives inside an incomplete invocation are rejected.
- `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else`, `#endif` and both forms of `defined`.
  Excluded branches do not contribute declarations, shader operations or reflection.
  Unlike a C preprocessor, GLSL diagnoses an evaluated undefined identifier in a
  condition. Logical short circuit permits undefined identifiers in skipped operands.
- Conditional arithmetic uses signed 32-bit values, decimal/octal/hex literals in
  0..2147483647, unary signs, logical/bitwise operators, shifts, comparisons and the
  ordinary arithmetic operators. Invalid division, unsupported literal ranges,
  arithmetic overflow and shifts outside 0..31 are diagnosed. These limits are a
  declared subset; unsigned conditional values are not evaluated as floats or signed
  approximations. Ternary expressions are not GLSL preprocessor operators.
- `GL_ES`, `__VERSION__`, `__LINE__`, `__FILE__` and
  `GL_FRAGMENT_PRECISION_HIGH`. The last is 1 because this backend provides fragment
  highp using its actual f32 format. The source API supplies one string, so `__FILE__`
  is 0. Physical line tracking includes normalized newlines, continuations and comments;
  a macro body expands `__LINE__` at its invocation site.
- Backslash-newline continuation before comment stripping, including WebGL 1's explicit
  continuation requirement. Comment contents and quoted preprocessing tokens are not
  expanded. Non-GLSL characters in eliminated branches can disappear before the GLSL
  character/grammar check; active string or character expressions remain unsupported.
- `#error` produces a compile diagnostic. Unknown pragmas are ignored as GLSL requires.
  `optimize(on/off)` and `debug(on/off)` are recognized implementation-dependent hints,
  checked outside function definitions; they do not expose a new optimizer or debugger.

The WebGL rule forbids `defined` generated by macro expansion in a conditional. Builtin
macro redefinition/undefinition and reserved macro names are diagnosed. Names beginning
`GL_`, `webgl_` or `_webgl_` are unavailable; ESSL 100 also reserves consecutive
underscores. ESSL 300 treats non-builtin consecutive-underscore names as reserved by
convention rather than automatically invalid.

## Version declarations

Without a declaration the source is ESSL 100. `#version 100` must precede source tokens
and other directives. `#version 300 es` must occupy the first physical line and end in
a newline, before comment processing and continuations. Its version number cannot be
supplied by a macro. Context/source version checks and mixed-version link rejection
remain in the existing compiler. WebGL 2's 1024-character token limit also applies to
ESSL 100 sources in that context; WebGL 1 retains 256.

## Bounds and deferred operations

Input and expanded source each have a 64 KiB limit. Preprocessing admits at most 16384
tokens, 256 distinct user macro names, 32 parameters/arguments, 32 expansion levels and
64 conditional/expression/argument-parenthesis levels. A global 131072-step and 1 MiB
token-materialization budget counts nested prescans and repeated substitutions. It
cannot be reset by starting another directive. The existing typed-expression and draw
budgets still apply after preprocessing.

Active `#line`, `#extension`, `#include`, variadic macros, stringification and token
pasting produce explicit errors. The subset does not implement unsigned conditional
arithmetic or the full integer range/overflow semantics of every GLSL version.
Unsupported directives in excluded groups do not execute. General GLSL loops, arrays,
integer variables, unsupported sampler types and other evaluator gaps remain separate
work. Diagnostics from preprocessing name a physical source line; the later shader
parser has not gained a full mapping from expanded tokens back to every source span.

## Regression sources and evidence

Own backend tests exercise 100/300 color and texture pixels, reflection after branch
elimination, physical-line builtins and atomic compile errors. Module tests include
recursive rescanning, comments, malformed directives and resource growth. The page
fixture `tests/pages/webgl-preprocessor.html` drives both JavaScript contexts and has
Script/Engine tests and a reference image page.

External source inspection is pinned to Khronos WebGL revision
`39443210f7f81db4773eb104facadfb85d05dfa4`:
[tricky macro expansion](https://raw.githubusercontent.com/KhronosGroup/WebGL/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/glsl/preprocessor/macro-expansion-tricky.html),
[comments](https://raw.githubusercontent.com/KhronosGroup/WebGL/39443210f7f81db4773eb104facadfb85d05dfa4/sdk/tests/conformance/glsl/preprocessor/comments.html).
The tiny discarded recursive-argument pattern is covered by our own shader regression;
this is not a report of executing the complete external harness.

The version aliases used by
[Three.js r180 WebGLProgram](https://raw.githubusercontent.com/mrdoob/three.js/0af9729d0c143a86a1d725d6e2c3ad83301f3f34/src/renderers/webgl/WebGLProgram.js)
inspired a small independent texture fixture. That source is pinned at
`0af9729d0c143a86a1d725d6e2c3ad83301f3f34`; an entire Three workload still requires
additional shader types, APIs and rendering features. Test presence and source
inspection alone do not establish an executed pass, CTS score or performance result.
